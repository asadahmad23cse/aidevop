📐 Metric Definitions & Calculation Methodology

🎯 Correctness / Accuracy

Score 0–2 scale normalized to 0–1. Required-fact coverage ≥75% scores 2, ≥40% scores 1, else 0. Out-of-scope queries score 2 only upon explicit abstention.

Correctness = Σ(Score_i) / (2 × N)
🛡️ Hallucination Rate

Share of factual response sentences lacking at least 35% token overlap with any retrieved chunk in the context window.

Hallucination = (Unsupported Sentences) / (Total Factual Sentences)
🔍 Retrieval Quality (P@3, Recall@3, MRR)

Evaluates FAISS semantic search against ground-truth document IDs. Precision@3 = 0.333 (1 target chunk / top-3 returned). Recall@3 = 1.000, MRR = 1.000.

MRR = (1 / rank_of_first_relevant_doc)
⏱️ Response Latency & Tokens

Wall-clock time from sending non-streamed Ollama generation request to response completion. Tokens = prompt_eval_count + eval_count from Ollama metadata.

Latency = T_response_end - T_request_start (ms)
💻 CPU, RAM & GPU Consumption

System CPU % and process RSS sampled every 200 ms during generation. VRAM represents Ollama model memory allocation on Intel Arc GPU.

Sampled every 200ms during active inference

Exercise 4

Evidence-Based Comparative Analysis

Detailed answers to the core research questions supported by quantitative benchmark evidence and quality–latency–resource trade-off findings.

Evidence-Driven Insights
1

Which model provides better accuracy?

StarCoder2 3B achieves the highest medical accuracy at 58.0% correctness, leading both Code Llama 7B (18.0%) and Qwen2.5-Coder 3B (18.0%) by +40 percentage points. However, for cross-file repository understanding, Code Llama 7B leads with 56.2% correctness.

Evidence: 58.0% vs 18.0% (Medical) | 56.2% vs 37.5% (Repo)
2

Which model produces fewer hallucinations?

StarCoder2 3B produced the fewest hallucinations at 11.1% on medical QA (vs 27.1% for Qwen and 44.4% for Code Llama) and 3.6% on repository tasks. It adhered closely to provided chunks rather than fabricating dosage or diagnosis facts.

Evidence: 11.1% (StarCoder2) < 27.1% (Qwen) < 44.4% (CodeLlama)
3

Which model provides better retrieval-based responses?

Because retrieval context was identical across all models (same FAISS top-3 chunks), differences reflect context utilization. StarCoder2 3B synthesized context into answers most accurately, while Code Llama frequently ignored retrieved chunks in favor of parametric pre-training memory.

Evidence: StarCoder2 fact-coverage delta +1.000 on MED-010
4

Which model has lower response latency?

Qwen2.5-Coder 3B is by far the fastest model with a mean latency of 9.26 seconds per answer (median 8.84 s, p95 13.99 s) — 2.1× faster than StarCoder2 (19.44 s) and 4.5× faster than Code Llama 7B (42.32 s).

Evidence: Qwen 9.26 s < StarCoder2 19.44 s < Code Llama 42.32 s
5

Which model requires fewer computational resources?

StarCoder2 3B requires the least resources: lowest model VRAM allocation (1,789 MB), lowest mean CPU load (8.5%), and lowest peak RAM (11,291 MB). Code Llama 7B requires 3.19× more VRAM (5,710 MB) and 23.0% CPU.

Evidence: VRAM 1,789 MB (StarCoder2) vs 2,055 MB (Qwen) vs 5,710 MB (CodeLlama)
6

Is the most accurate model also the most efficient? (Quality-Latency Trade-Off)

Nuanced Trade-Off: StarCoder2 3B is the most memory-efficient and accurate model, but not the fastest. Qwen2.5-Coder offers 10.18s faster latency per question at the cost of 40% correctness. Code Llama 7B offers superior repository understanding (56.2%) but at a high cost of 78.89s latency and 5.7GB VRAM.

Trade-off: Accuracy leader (StarCoder2) vs Speed leader (Qwen) vs Repo leader (CodeLlama)

Repository & Cross-Module Codebase Understanding

8 Codebase Probes
⚠️ Limitations of Flat Embedding Search for Codebase Navigation

While FAISS successfully answers localized queries when chunks co-occur, empirical evaluation reveals clear architectural bottlenecks in flat chunk-based retrieval:

  • Low Multi-File Recall (0.338): Top-3 retrieval frequently captures multiple chunks from a single verbose file, starving other essential architectural dependencies.
  • No Call-Graph or AST Resolution: Semantic similarity fails to track caller/callee relationships, import chains, or variable symbol scopes across modules.
  • Chunk Boundary Truncation: 256-token chunking splits functions and interface definitions, discarding critical structural context.
  • Bridge to Week 5: These exact limitations motivate semantic code graphs and Sourcegraph-style code intelligence for repository navigation next week.
