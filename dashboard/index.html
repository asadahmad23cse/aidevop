01 📄

Document Ingestion

Load raw medical QA data from the ChatDoctor-HealthCareMagic-100k dataset and 200 synthetic examples. Raw data = unprocessed text pairs (question + answer).

Input: Hugging Face Dataset + OpenAI API Output: 1,700 raw QA pairs (JSONL)
02 ✂️

Text Chunking

Split each document into smaller, overlapping chunks (256 tokens each with 50-token overlap). This ensures no context is lost at boundaries, and each chunk is a searchable unit.

Strategy: Fixed-size + Overlap Chunk Size: 256 tokens
03 🔢

Embedding Generation

Each text chunk is converted into a dense vector (768-dim) using a Sentence Transformer embedding model. Similar meanings → vectors close together in space.

Model: all-MiniLM-L6-v2 Dimension: 384-d vectors
04 🗄️

Vector Store Indexing

All chunk vectors are stored in a FAISS (Facebook AI Similarity Search) index for fast approximate nearest-neighbor lookup. This is the "knowledge brain" of the RAG system.

Index: FAISS IVF-Flat Search: Cosine Similarity
05 🔍

Query Embedding

When a user asks a medical question, it's embedded into the same vector space using the same embedding model — so it's directly comparable with all stored document chunks.

Same Model: all-MiniLM-L6-v2 Output: 384-d query vector
06 🎯

Semantic Retrieval

FAISS finds the Top-K most similar chunks (K=3) by computing cosine similarity between the query vector and all stored vectors. Only the most relevant medical knowledge is retrieved.

Method: Cosine Similarity (Top-3) Latency: ~5ms per query
07 📝

Prompt Augmentation

The retrieved chunks are injected into an instruction prompt alongside the user's original question. The LLM sees both its training knowledge and fresh retrieved context.

Format: Alpaca Instruction Template Context Window: 512 tokens
08 🤖

LLM Generation

The Code Llama (via Ollama API) / fine-tuned LLM generates a structured response grounded strictly in retrieved clinical context — eliminating hallucinations.

LLM: Code Llama (Ollama) Grounding: FAISS Context
